## Responsive design — components

Mobile/desktop split is Tailwind v4's `md:` (≥768px) — the only breakpoint used.

- **Tables vs cards**: every list page keeps a desktop `<table>`. Row components render two siblings: a `<tr className="md:hidden">` with `colSpan` wrapping a mobile card, and a `<tr className="hidden md:table-row">` with the original cells. The parent table is `table-auto md:table-fixed` so the colgroup pixel widths don't force horizontal overflow on mobile. See `src/components/TransactionRow.tsx` for the reference implementation (tap-to-expand reveals note + Edit/Delete; tapping Edit reuses the same `editing` state with a stacked form). For pages where the note overflow isn't an issue (`/categories`, `/plan`, `/expenditures`) the rows stay tables and only the icon buttons get a 40px `inline-flex min-w-10 min-h-10` hit-area wrapper.
- **Primary action on mobile**: the inline create form on `/transactions` is `hidden md:block`. Mobile uses `src/components/TransactionCreateSheet.tsx` — a FAB anchored at `bottom-[calc(env(safe-area-inset-bottom,0px)+5rem)]` that opens a bottom sheet (`fixed inset-x-0 bottom-0 z-50 rounded-t-2xl`) reusing the same `createTransaction` server action via `useActionState`. The sheet auto-closes on successful submit by comparing `state.successCount` against a stored `lastSeenSuccess` in render (not in an effect — avoids `react-hooks/set-state-in-effect`). Sheet inputs use `text-base` to prevent iOS focus-zoom.
- **FilterPanel dropdown**: panel uses `w-[min(15rem,calc(100vw-2rem))] md:w-60` so it never spills past the right edge on narrow screens; the trigger summary truncates at `max-w-[10rem] md:max-w-[14rem]`.
- **Charts**: both chart containers use `h-72 md:h-[380px]`. The pie chart uses percentage radii (`innerRadius="37%"` / `outerRadius="63%"`) so it scales with the container while preserving the original 70/120px size at the desktop height.
