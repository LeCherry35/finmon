## Responsive design — components

Mobile/desktop split is Tailwind v4's `md:` (≥768px) — the only breakpoint used.

- **Tables vs cards**: every list page keeps a desktop `<table>`. Row components render two siblings: a `<tr className="md:hidden">` with `colSpan` wrapping a mobile card, and a `<tr className="hidden md:table-row">` with the original cells. The parent table is `table-auto md:table-fixed` so the colgroup pixel widths don't force horizontal overflow on mobile. See `src/components/TransactionRow.tsx` for the reference implementation (tap-to-expand reveals store + note + Edit/Delete; tapping Edit reuses the same `editing` state with a stacked form). The desktop table column set is Date · Category · Store · Status · Amount · actions: a `StatusBadge` (colour-coded `processing`/`unverified`/`ready_to_verify`/`verified`, falling back to `unverified` for unknown values) replaced the desktop Note column, so on desktop the note is neither shown nor editable inline — it lives only in the mobile expanded card and its edit form. `store` (optional merchant name) shows as its own desktop column (em-dash when null) and is inline-editable; on mobile it sits in the expanded card and its edit form. The mobile card shows the badge next to the date. For pages where the note overflow isn't an issue (`/categories`, `/plan`, `/expenditures`) the rows stay tables and only the icon buttons get a 40px `inline-flex min-w-10 min-h-10` hit-area wrapper.
- **Primary action on mobile**: the inline create form on `/transactions` is `hidden md:block`. Mobile uses `src/components/TransactionCreateSheet.tsx` — a FAB anchored at `bottom-[calc(env(safe-area-inset-bottom,0px)+5rem)]` that opens a bottom sheet (`fixed inset-x-0 bottom-0 z-50 rounded-t-2xl`) reusing the same `createTransaction` server action via `useActionState`. The sheet auto-closes on successful submit by comparing `state.successCount` against a stored `lastSeenSuccess` in render (not in an effect — avoids `react-hooks/set-state-in-effect`). Sheet inputs use `text-base` to prevent iOS focus-zoom.
- **Receipt scanning on create**: both the desktop form and the mobile sheet embed the shared `ReceiptUpload` (`src/components/ReceiptUpload.tsx` — a nameless file input, so the image never rides along in the form's own submission; it downscales the photo to a JPEG data URL via canvas, falling back to `FileReader` under jsdom). When a receipt is staged the submit button reads "Scan & add" and a hidden `has_receipt` input makes `createTransaction` start the row `processing`. The shared `useReceiptScanCreate(state)` hook holds the staged image and, on the new `lastTxId`, fires `scanReceiptForTransaction` fire-and-forget (in an effect, guarded by a ref) so the row is added independently of the scan; it flips Processing → Ready to verify / Unverified live when the scan resolves.
- **Products modal**: opening `src/components/ProductsModal.tsx` is row-driven on desktop — clicking anywhere on a `TransactionRow` (`cursor-pointer`, `hover:bg-zinc-50`) opens it, with `e.stopPropagation()` on the Edit/Delete buttons so they don't also trigger it; there is no separate desktop "Products" button. Mobile keeps a full-width box-icon "Products" button in the expanded card. The modal renders via `createPortal(..., document.body)` to escape the `<tbody>` (a `<div>` can't be a `<tr>` sibling) — no SSR mount guard is needed because it only renders after a client click. It lists `tx.products` (live: `addProduct`/`updateProduct`/`deleteProduct` call `revalidatePath("/transactions")`, which refreshes the row's props while the modal stays open), with inline per-item edit/delete (same confirm-twice delete pattern as the row) and an add form; both reuse a `ProductFieldsEditor`. A non-blocking amber hint flags when product costs don't sum to `tx.amount` (Reading A — divergence is allowed). `ReceiptScanner` (replacing the former `MockUpload` stub) uploads a receipt photo and attaches the AI-parsed line items as products: it uses the shared `ReceiptUpload` picker + `useTransition` → `scanReceiptForTransaction` (`src/actions/receipt.ts`), shows "Scanning…", and the products list refreshes live off the same `revalidatePath("/transactions")` the add/edit/delete paths rely on.
- **FilterPanel dropdown**: panel uses `w-[min(15rem,calc(100vw-2rem))] md:w-60` so it never spills past the right edge on narrow screens; the trigger summary truncates at `max-w-[10rem] md:max-w-[14rem]`.
- **Charts**: both chart containers use `h-72 md:h-[380px]`. The pie chart uses percentage radii (`innerRadius="37%"` / `outerRadius="63%"`) so it scales with the container while preserving the original 70/120px size at the desktop height.
